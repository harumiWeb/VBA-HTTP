# VBA-HTTP user guides

This directory is the public-facing documentation hub for VBA-HTTP. It is
organized around the tasks a workbook author performs: install the modules,
create requests, handle results, add reliability, stream files, and choose
transport capabilities.

## Start here

1. [Getting started](getting-started.md) — install the VBA-Web-style source
   package and send the first request.
2. [API reference](api-reference.md) — the complete public factory, class,
   interface, enum, and error surface.
3. [Requests and responses](requests-and-responses.md) — URL resolution,
   headers, body ownership, decoding, and status handling.
4. [Reliability and batches](reliability-and-batches.md) — retries, deadlines,
   cancellation, concurrency, and per-item results.
5. [Streaming](streaming.md) — constant-memory downloads, uploads, multipart,
   progress, and cleanup guarantees.
6. [Transport capabilities](transport-capabilities.md) — COM versus native
   WinHTTP, protocol/decompression/proxy options, and capability boundaries.
7. [Security and state](security-and-state.md) — TLS, authentication,
   redirects, cookies, diagnostics, and redaction.
8. [Distribution](distribution.md) — source modules, optional workbooks, and
   GitHub Release assets.
9. [Examples](examples.md) — copy-paste VBA recipes for common operations.
10. [Compatibility](compatibility.md) — supported Office/runtime boundary and
    evidence requirements.

## Documentation layers

The guides are the stable explanation intended for application authors. The
normative contracts live in [`../specs/`](../specs/README.md), and the reasons
behind material architectural decisions live in [`../adr/`](../adr/README.md).
When a guide and an implementation appear to disagree, treat the current
specification and its tests as authoritative and open a documentation issue.

The historical [`../API.md`](../API.md) page remains as a compatibility entry
point and links back here. New public API documentation belongs in this
directory rather than in the README.

## Scope at a glance

- Primary distribution: VBA-Web-style source modules installed into a closed
  workbook.
- Optional artifacts: filtered XLSM/XLAM workbooks generated by xlflow.
- Supported runtime: Windows x64 Office with WinHTTP.
- 32-bit Office is currently unverified and has no official release guarantee;
  HTTP/3/QUIC remains unsupported by policy; XLAM is not the primary package.
  See [Compatibility](compatibility.md).
- The default backend is late-bound `WinHttp.WinHttpRequest.5.1`; native
  WinHTTP is opt-in for streaming and advanced capabilities.
